# SWOT - CI/CD Process (2026-06-16)

## Scope

This SWOT evaluates the current GitHub Actions-based CI/CD process for Chromatic Harness v2, focusing on reliability, speed, governance coverage, and release safety.

---

## Strengths

- Strong governance depth already exists in CI, including security, schema, intake-loop, lock-metrics, and policy gates.
- Cross-platform concurrency coverage is present via Linux + Windows matrix runs.
- PR governance and artifact uploads provide good auditability for review and incident follow-up.
- Security gate now includes dependency scanning instead of silently skipping dependency checks.
- Pre-push local gate and CI both enforce quality, reducing branch drift between local and remote validation outcomes.

---

## Weaknesses

- Lint scope was previously partial (`src/` and `tests/`), allowing script and runtime folders to bypass Ruff checks.
- Markdown quality checks were not systematically enforced in CI, allowing style regressions in PDR and handoff docs.
- Workflow breadth has grown large; runtime per PR can become expensive and noisy, slowing feedback loops.
- Several gates are advisory (`continue-on-error`) and can mask quality degradation if operators do not inspect artifacts.
- Legacy formatting debt (many files not Ruff-formatted) prevents full-repo formatting gate activation today.

---

## Opportunities

- Shift-left doc quality by linting changed markdown files in CI (implemented) to prevent net-new markdown drift.
- Expand automated lint evidence reporting (summary comments) so reviewers can triage failures faster.
- Introduce tiered CI lanes:
  - fast lane for lint + governance sanity + targeted tests
  - deep lane for full suites and matrix runs
- Add explicit required-check policy mapping in docs so advisory vs blocking gates are intentional and transparent.
- Gradually burn down formatting debt and then promote `ruff format --check .` to a full-repo gate.

---

## Threats

- CI fatigue: too many non-actionable warnings can train maintainers to ignore critical failures.
- Toolchain drift (actions, lint versions, scanner behavior) can create surprise breakages or false negatives.
- Security and compliance blind spots can reappear if advisory gates remain unmonitored.
- Rising CI runtime and queue contention can incentivize bypass behaviors and reduce gate effectiveness.

---

## Immediate Actions (Implemented in this cycle)

1. Expanded Ruff lint gate in CI from `src/ tests/` to repository-wide `ruff check .`.
2. Added markdown lint automation in CI for changed markdown files using `markdownlint-cli2`.

---

## Next Actions (Recommended)

1. Convert key advisory gates to required where signal quality is proven stable.
2. Create a CI gate policy matrix doc mapping each check to risk class, owner, and enforcement level.
3. Start a staged campaign to auto-format legacy files and then enable full-repo `ruff format --check .`.
4. Add CI performance budget tracking (median runtime, p95 runtime, queue wait) as a weekly KPI.
