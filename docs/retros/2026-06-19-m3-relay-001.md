## Learnings

### 1. langsmith pytest plugin breaks entire pytest startup on pydantic version mismatch
The `langsmith` package registers a `pytest11` entrypoint; when `pydantic_core` is mismatched it raises `ImportError: cannot import name 'validate_core_schema'` before any tests collect. There is no `-p no:langsmith` workaround because the crash happens at plugin loading, before arg parsing. Fix: `pip install --upgrade pydantic pydantic-core langsmith` or remove `langsmith` from dev deps.

**Action:** Track as mc-4lu09 (P2, env-broken). Do not block impl work on broken pytest env — log and defer.

### 2. stdlib http.server is sufficient for a single-endpoint localhost relay
No FastAPI, no uvicorn, no external deps needed. stdlib `HTTPServer` handles the relay use case cleanly — one `/health` GET and one `/complete` POST. Zero install overhead, works on any Python 3.x.

**Action:** Prefer stdlib for localhost bridge scripts; only reach for FastAPI when async concurrency or middleware is genuinely needed.

### 3. lru_cache on import-inside-function eliminates repeated sys.path manipulation
When `_infer_levels` was called per ledger row (11k+ rows), it ran `sys.path.insert` + `from token_level_inference import infer_levels` every time. With `@functools.lru_cache(maxsize=64)`, the import runs once on first cache miss; all subsequent calls return the cached tuple. The cache key is the model string (~10 distinct values in practice).

**Action:** Any function that does a lazy import in a hot loop should be `lru_cache`-wrapped.
