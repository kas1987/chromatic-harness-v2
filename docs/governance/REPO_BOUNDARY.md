# Chromatic Harness v2 — Git Purpose & Source-of-Truth Boundary

## Purpose of this document

Define what belongs in Git, what belongs outside Git, and why. The harness grew from a small agent-runtime repo into a multi-concern workspace. Without a published boundary, runtime telemetry, session state, and generated audit dumps leaked into the source-of-truth store. This doc is the new contract.

## What Git is for

Git holds the **durable, portable, reviewable core** of the harness:

| Category | Examples | Why in Git |
|----------|----------|------------|
| Source code | `scripts/`, `tests/`, `02_RUNTIME/`, `05_FRONTEND_CONSOLE/` | Reproducible builds and CI |
| Configuration | `config/`, `.gitignore`, `.vscode/` (shared tasks), `.claude/` (hooks) | Machine-local variants use `.local` suffixes and are ignored |
| Canonical docs | `docs/`, `AGENTS.md`, `AGENT_OPERATIONS.md`, `00_SOURCE_OF_TRUTH/`, `04_PLAYBOOKS/` | Human + agent reference |
| Durable manifests | `config/dev_cli_manifest.yaml`, `01_PROTOCOLS/MCP/MCP_TOOL_MANIFEST.md` | Cross-rig consistency |
| Skills | `.agents/skills/`, `docs/agents/` | Agent behavior contracts |
| Seed data | `07_LOGS_AND_AUDIT/seed_state/issue_to_bead.json` | Idempotent starting state |
| Tests & gates | `tests/`, CI workflows | Quality enforcement |

## What Git is NOT for

| Category | Examples | Where it lives |
|----------|----------|----------------|
| Runtime logs | `07_LOGS_AND_AUDIT/AGENT_RUN_LOG.jsonl`, `07_LOGS_AND_AUDIT/drift/*.json` | Local filesystem; rotated; analyzed by scripts |
| Session telemetry | `.agents/handoffs/closeout_telemetry_*.json`, `.agents/context/*.md` | Per-session; ephemeral |
| Generated audit dumps | `07_LOGS_AND_AUDIT/security/*_latest.json`, `07_LOGS_AND_AUDIT/ci/*_latest.json` | Regenerated by scripts; archive externally if durable history is needed |
| Local state DBs | `07_LOGS_AND_AUDIT/active_sessions.sqlite3`, `.beads/interactions.jsonl` | Runtime only |
| Coverage snapshots | `07_LOGS_AND_AUDIT/coverage/*.json` | CI artifact store or local temp |
| Per-run reports | `00_META/observability/reports/*.md` | Generated; publish to artifact store |
| Plugin cache | `.codex/`, `02_RUNTIME/.agents/` | Local tool state |

## Decision criteria

Use this checklist before adding a file to Git:

1. **Does another machine need this to run CI or boot an agent?** → Yes → Git
2. **Is it generated by a script from source/config?** → Yes → ignore it
3. **Does it contain machine-local paths, session IDs, or timestamps?** → Yes → ignore it
4. **Is it an audit artifact that must survive for compliance?** → Yes → Git OR external archive, not auto-generated local dump
5. **Would a fresh clone break without it?** → Yes → Git (unless it is regenerated on first boot)

## Consequences of the boundary

- `git status` should now show primarily intentional source changes, not hundreds of telemetry files.
- Agents can rely on Git for stable skill definitions and playbooks.
- Runtime scripts can write freely to `07_LOGS_AND_AUDIT/` and `.agents/` without polluting commits.
- Future CI should regenerate `docs/PRE_SESSION_AND_TOOLS.md` and `config/pre_session/inventory.snapshot.json` from the local MCP descriptor path rather than expecting a committed snapshot.

## Maintenance

When a new runtime directory appears:

1. Ask: is it source/config/docs/skills/tests, or runtime telemetry?
2. If runtime, add it to `.gitignore`.
3. If it was accidentally tracked, `git rm --cached <path>` to stop tracking without deleting local files.
4. Update this doc and the Mermaid diagrams in `docs/governance/REPO_ARCHITECTURE.md`.
